# Design Trait Library

This library preserves useful knowledge from the former preset system without selecting a complete aesthetic. Load only the families relevant to the approved DESIGN_GENOME.

Traits are ingredients. Do not copy a whole row, bind it to a business category, or use the family label in INTENT. Combine compatible properties only when every choice has a reason.

## Reusable properties

### Composition

- permanent side rail that changes function by section
- dominant object crossing a structural boundary
- document index controlling the content field
- image sequence acting as section punctuation
- route or ledger replacing the usual feature grid
- full-width type field interrupted by a real interface or artifact

### Typography

- compressed sans for short operational nouns
- wide grotesk for slow horizontal pacing
- serif used only for evidence, quotations, or material description
- mono reserved for actual code, identifiers, or machine state
- single family with strong optical-size or width contrast
- variable font axis tied to interaction when legibility remains stable

Do not default to any named pair. Choose available, licensed typefaces and explain each role.

### Geometry

- thin rules and large rectangular planes
- route-like polylines connected to real stages
- logo-derived angles or radii
- irregular crop windows derived from source imagery
- dense table rhythm interrupted by one oversized field
- boundary crossings that mark state change

### Material

- flat ink and paper
- luminous screen plane
- controlled glass on a small functional surface
- metal or translucent product material from a real asset
- grain tied to source photography or print reference
- no material effect; typography and space carry the direction

### Motion

- mechanical stepped state changes
- scroll-linked object inspection
- discrete document disclosure
- route progress
- typographic width or axis response
- hard cut used once to mark a real narrative change
- no primary animation when still composition is stronger

### Navigation

- fixed vertical rail
- document index
- in-flow chapter markers
- product-state tabs
- route nodes
- compact conventional header when navigation is not part of the concept

## Compatibility

Properties combine well when they share a structural cause. Examples:

- institutional composition + editorial typography + route geometry + mechanical motion can all express a public process;
- product theatre + document captions can explain material and provenance;
- transaction ledger + monolithic restraint can make one verified workflow the visual anchor.

Reject combinations that require separate explanations for every effect. If a glass nav, grain overlay, serif accent, 3D object, and route animation each exist for different aesthetic reasons, the direction is incoherent.

## Responsive translation

Preserve the identity-bearing relationship, not the desktop coordinates:

- a permanent rail may become a top progress strip or in-flow index;
- an object crossing a boundary may become an intentional crop;
- a route may simplify to fewer meaningful nodes;
- a document hierarchy may become collapsible without losing its numbering or geometry;
- expensive motion may become discrete states while the motif remains visible.
